# dsh-history 用户手册

> ⚠️ **重要声明**：本项目为**个人使用而开发**，仅按作者自身工作流演进。**后续仅修复严重 Bug，一般不接受新功能请求，也不承诺常规更新、维护或兼容性保证。** 使用前请知悉并自行评估风险。

> 本手册面向 **dsh 的日常使用者**（非开发者）。讲解如何安装、打开、阅读与使用"会话历史"功能，以及常见问题的解答。
>
> 开发者请看 [src/README.md](./src/README.md)（架构、源码、构建）。

---

## 1. 这是什么？

**dsh-history** 给 dsh 的聊天会话加上了"**时间旅行**"能力：

- 每轮对话（TURN 开始/结束）自动产生一个**历史快照**——就像 git 提交；
- 您可以**随时回到**任意历史时刻，把会话倒退回当时的状态；
- 回退是**原地生效**的：不新建会话、不开新窗口、不重启 dsh；
- 回退后，目标时刻之后的对话内容会**真正从会话记录中消失**（不是隐藏），就像从未发生过。

简单说：**聊天记录也能像 git 一样"回退版本"了。**

---

## 2. 安装与启用

> 该插件需要 dsh 管理员/插件安装步骤，若您使用的 dsh 环境已内置本插件，可跳过本节。

```bash
dsh plugin --profile web add <插件仓库路径>
```

并确保 profile 配置中包含该插件行（一般由安装流程自动写入）。安装完成后**重启 dsh** 生效。

**确认已生效**：重启后，会话标题栏（右上角）应出现一个 **HISTORY** 按钮（回退箭头图标），或能识别 `/history` 命令（见 §4）。

---

## 3. 快速上手（30 秒）

1. **打开历史面板**：点击标题栏的 **HISTORY** 按钮，或输入 `/history` 回车；
2. **看到的时间线**：一条垂直的 git 版本树，每一行 = 一个历史快照；
3. **回退**：点击任意一行 → 弹出「回档」对话框 → 选择一种回退方式 → 确认；
4. **关闭**：按 `Esc`，或点右上角 ✕，或点击面板外遮罩。

---

## 4. 如何打开历史面板

| 方式 | 操作 |
|---|---|
| **HISTORY 按钮** | 会话标题栏右上角，图标为"回退箭头 + HISTORY"，位于 Session log 按钮旁 |
| **命令** | 在输入框输入 `/history` 并回车（与官方命令同链路，即时弹出） |
| **快捷键** | 打开后按 `Esc` 关闭；关闭后再按 `Esc` 暂无再次打开 |

> 打开后面板会自动获得键盘焦点；Esc 随时关闭。

## 5. 面板界面导览

```
┌───────────────────────────────────────────────┐
│  ╭─ git 版本树 ──────────────────────────────╮ │
│  │  ①  ②  行内容                       ③  ④ │ │
│  ──────  ──────────────────────────────  ───── │
│  ●   │  BASELINE  test.md  api.ts    3bf8a1c   │
│  │   │  [USER] 检查此项目代码的历…            44 分钟前 │
│  │   │  [ASST] 已完成对本项目历…               │
│  │   │  test.md  index.ts                     │
│  ●   │  TURN 2 …                              │
│  │   │  …                                       │
│  └──────────────────────────────────────────────┘
```

| 编号 | 元素 | 说明 |
|---|---|---|
| ① | **结构线（rail）** | 彩色竖线连接父子快照；分叉处曲线；当前路保持彩色，被跳过的路显示灰色 |
| ② | **圆点** | 每个快照一个点；当前所在版本为**空心圆环**（HEAD），悬停会放大 |
| ③ | **commit 短 id** | 如 `3bf8a1c`（7 位十六进制），每个快照唯一 |
| ④ | **相对时间** | 如 `44 分钟前`，悬停显示完整时间 |

**行内容分类**：

| 行标签 | 含义 | 显示内容 |
|---|---|---|
| **BASELINE** | 工作区变动锚点（发送消息前，检测到文件变更时自动产生） | `BASELINE` + 变动文件 chips（如 `test.md` `api.ts`） |
| **TURN n** | 第 n 轮完整对话快照 | `[USER] 你的问题` / `[ASST] AI 的回答`（各一行预览）+ 变动文件 chips |
| **手动快照** | 您手动触发的快照 | 手动快照标记 |
| **回退 →** | 回退动作的标记行 | 目标 commit 短 id |

## 6. 如何读懂 git 版本树

### 6.1 竖线（rail）与分叉

- **一条竖直的彩色线** = 一条连续的"时间路"；
- **分叉（曲线）** = 您在某时刻回退后**继续对话且内容真的变了**，新内容形成一条**新路**（新颜色）；
- **灰色路线** = 被跳过的旧路（历史仍然可见，但非当前）。

### 6.2 当前版本（HEAD）

- 当前会话所在的快照标记为**空心圆环**；
- 无论回退到哪，圆环都跟随移动；
- 开头若干行默认显示 HEAD 前后各 20 条，滚动到顶部/底部自动加载更早/更晚的版本。

### 6.3 悬停查看更多

- 鼠标悬停任意行：该节点**整条祖先链**（一路向根的所有历史节点）会**高亮为蓝色**，其余节点变灰——一眼看清这版是从哪条路来的；
- 悬停时节点会放大 10%。

## 7. 回退（回档）操作

### 7.1 步骤

1. 点击想回去的那一行的**任意位置**；
2. 弹出「**回档**」对话框：
   ```
   回档
   要把当前会话退回到版本 3bf8a1c 吗？
   [仅会话]  [仅工作区]  [会话和工作区]
   ```
3. 选择回退方式（见 §7.2）；回退进行中按钮显示"处理中…"。

### 7.2 三种回退方式怎么选

| 按钮 | 效果 | 适用场景 |
|---|---|---|
| **仅会话** | 只把**会话记录**（对话内容）倒回目标版本，工作区文件不动 | 只想"重来一轮对话"，但代码/文件保持现在这样 |
| **仅工作区** | 只把**工作区文件**恢复到目标版本（代码回到当时），对话内容不动 | 只想"代码回到上一版"，但聊天上下文保留 |
| **会话和工作区** | 两者同时回退 | 完整回到当时的"对话 + 代码"状态（最常用） |

> **注意**：
> - 回退是**原地热重载**，会短暂"重建"当前会话视图（可能闪一下），然后继续正常对话；
> - 回退前会自动备份（`backups/` 目录），失败可恢复；
> - **会话正在运行中**（AI 正在回答）时拒绝回退；
> - **仅工作区**恢复不会删除目标版本里没有的新文件（避免误删）；若需要"严格回到当时"请自行处理多余文件。

### 7.3 回退后继续对话

- 回退后直接继续发消息即可；
- 如果之后**内容和回退前不同**，会形成一条**新路**（新分支，新颜色）；旧路仍在图上，可随时再跳回；
- 如果回退后**什么都没做**，不会留下任何多余节点。

## 8. 变动文件 chips（BASELINE / TURN 行内）

- 每个快照行会显示该快照时**变动过的文件名**（如 `test.md`、`index.ts`），一个文件一个高亮小块；
- 最多显示 **12 个**，更多时末尾显示 `… +N`（如 `… +237` 表示还有 237 个文件）；
- 鼠标悬停某个文件块可查看完整路径。

## 9.5 关于缓存（重要）

**回退不会让模型"重新理解"一切，也不会重建服务端前缀缓存。**

现代大模型（DeepSeek / Anthropic 等）使用**前缀缓存（KV cache）**：服务端把请求的公共前缀（system prompt + 工具定义 + 历史消息）物化为缓存单元；后续请求只要前缀**逐字节一致**，就直接复用缓存，首轮响应更快、成本更低。

### 为什么回退后缓存仍能命中

前缀缓存命中要求**新请求与前缀完全一致**。dsh 每次 resume 会**重建请求信封**（system prompt、工具集、模型路由），如果重建方式与回退前不同，前缀立刻分叉，缓存永远失效。

本插件在回退时做两件事，确保信封与历史状态**逐字节一致**：

1. **恢复 agent preset**：重新挂载目标版本当时使用的工具集与系统提示段（`agentPresets.mount`）；
2. **恢复模型路由**：从目标文件最后一条请求记录中读取 provider / model，恢复当时的路由配置。

三者（消息前缀 + 信封 + 路由）对齐后，回退后的首轮请求与"当时真实发生的那轮"前缀一致，**服务端前缀缓存继续命中，无需重建**（实测回退后首轮 `cacheRead > 0`）。

### 降级与限制

- **preset 无法挂载时**（例如 preset 已被删除）：自动降级为裸 resume，此时面板会提示 ⚠ `compositionWarning`——会话可用，但缓存大概率失效（首轮响应变慢）。
- **工作区指令（AGENTS.md 等）变化**也会改变 system prompt 前缀：选择"会话和工作区"一起回退时按目标时间对齐，指令一致、缓存保持；只回退会话而工作区已被后续修改时，前缀与目标真实状态的自然差异属预期行为。
- 目标文件损坏 / 无法解码：按裸 resume 处理（不失败，仅缓存退化）。

### 一句话总结

> **回退是"回到当时的请求状态"，而不是"重建一切"**——信封与路由都被恢复，服务端前缀缓存被复用，响应速度与原来一致。

## 10. 常见问题（FAQ）

**Q1：有些回合没有 BASELINE 行，正常吗？**
正常。BASELINE 只在**检测到工作区文件发生变动**时产生；如果两轮之间没改任何文件，就不会有冗余的 BASELINE 节点。

**Q2：文件 chips 超过 12 个看不到全部？**
是的，面板只展示前 12 个并显示 `… +N`；需要完整清单时可以使用「导出影子仓库」到本地后用 git 工具查看。

**Q3：回退后 AI 的上下文会怎样？**
会话记录被物理替换为目标时刻版本——目标之后的所有消息/工具调用都不在记录中。同时插件会**恢复当时的模型路由与工具配置**，尽可能保持前缀缓存命中（回退后首轮响应速度更好）。详细说明见 §9.5「缓存问题」。

**Q4：回退后想反悔怎么办？**
回退是双向的：旧版本仍在图上（原路或新路），再点击原来的行即可再跳回。回退前的文件也有自动备份。

**Q5：为什么有时候回退按钮是"处理中…"很久？**
正在重建会话视图或恢复工作区文件（大工作区可能较慢）；完成前请勿重复点击。

**Q6：能否在多个 dsh 实例同时操作同一会话的历史？**
不建议。插件依赖"独占会话"语义，回退期间会话会被短暂 detach；多个实例并发操作可能引起冲突。

**Q7：历史数据存在哪里？**
`$DSH_HOME/.dsh-history/`：`repos/`（会话影子仓库）、`repos-ws/`（工作区影子仓库）、`backups/`（回退前备份）。

## 11. 权限与安全说明

- 历史面板只读取**本机**的影子仓库（loopback 白名单），不对外提供网络访问；
- 快照/回退影响**当前会话与当前工作区**，提交与备份均在本机；
- 「清理旧分支」等破坏性操作（如适用）为两次确认，且不可恢复——请谨慎使用。
