# Bug 分析报告：工作区快照 .gitignore 多级路径匹配失效导致影子仓库体积异常膨胀

## 一、 问题背景与现象

在 DeepSeek Harness 会话快照管理中，某些会话的影子 Git 仓库体积异常巨大。

* **典型案例仓库**：
  `C:\Users\Donzy\.dsh\.dsh-history-rewind\repos-ws\session-session-e4700bfd-275e-4d35-82a1-ccb4ed67d72c.git`
* **问题现象**：
  开发者明明在项目根目录 `.gitignore` 中明确配置了 `/src-tauri/target/`、`**/*.rs.bk` 等过滤规则，但影子仓库依然极速膨胀至 **2.65 GB**（Loose Git Objects 达 11,108 个），快照解压后的物理文件高达 **13.14 GB**。

## 三、 根本原因分析 (Root Cause)

问题的核心出在 `dsh-history-rewind` 插件对工作区进行快照扫描时的过滤逻辑：`src/workspace.ts` 中的 `compileExcludes` 和 `walkFiles` 函数。

### 缺陷代码（`src/workspace.ts`）

```typescript
function globToRegex(pattern: string): RegExp {
  const escaped = pattern.replace(/[.+^${}()|[\]\\]/g, '\\$&').replace(/\*/g, '.*').replace(/\?/g, '.')
  return new RegExp(`^${escaped}$`)
}

export function compileExcludes(patterns: readonly string[]): (rel: string, isDir: boolean) => boolean {
  const rules: ExcludeRule[] = []
  for (const raw of patterns) {
    if (raw.length === 0) continue
    let pattern = raw
    let dirOnly = false
    if (pattern.endsWith('/')) {
      dirOnly = true
      pattern = pattern.slice(0, -1)
    }
    let anchored = false
    if (pattern.startsWith('/')) {
      anchored = true
      pattern = pattern.slice(1)
    }
    if (pattern.length === 0) continue
    rules.push({ regex: globToRegex(pattern), dirOnly, anchored })
  }
  return (rel, isDir) => {
    const name = basename(rel)
    const isRoot = !rel.includes('/')
    for (const rule of rules) {
      if (rule.dirOnly && !isDir) continue
      if (rule.anchored && !isRoot) continue
      if (rule.regex.test(name)) return true
    }
    return false
  }
}
```

### 具体失效机制

#### 1. 匹配目标被强制限制为 `basename(rel)`（单级文件名）
* 对于规则 `/src-tauri/target/`，剥除首尾斜杠后得到的 pattern 为 `src-tauri/target`，生成正则 `/^src-tauri\/target$/`。
* `walkFiles` 递归进入 `src-tauri` 目录检查 `target` 目录时，`rel = "src-tauri/target"`，而 `name = basename(rel) = "target"`。
* 正则 `/^src-tauri\/target$/` 去匹配 `"target"` 永远为 `false`。

#### 2. `anchored` 判定与 `isRoot` 逻辑产生截断（Short-circuit）
* 开头带 `/` 的规则会被标记为 `anchored = true`。
* 过滤规则判定：`isRoot = !rel.includes('/')`。
* 当检查到 `src-tauri/target` 时，因为包含路径分隔符 `/`，所以 `isRoot = false`。
* 执行到判断语句：
  ```typescript
  if (rule.anchored && !isRoot) continue
  ```
  此时 `rule.anchored === true` 且 `!isRoot === true`，该规则在第一时间直接被 `continue` 略过，根本不会执行后续匹配。

#### 3. 缺乏 Globstar（`**`）和通配符层级支持
* 简单的字符串替换 `pattern.replace(/\*/g, '.*')` 会将 `**/*.rs.bk` 转换为带 `/` 的正则，同样因为匹配对象是无 `/` 的 `basename` 而全部失效。

#### 为什么根目录规则（如 `/node_modules/`）可以正常工作？
对于 `/node_modules/`：
* `pattern = "node_modules"`，`regex = /^node_modules$/`，`anchored = true`。
* 扫描到根目录下 `node_modules` 时：`rel = "node_modules"`，`isRoot = true`，`name = "node_modules"`。
* 既未触发 `if (rule.anchored && !isRoot) continue`，正则匹配也完全吻合，因此根目录的一级目录能被正确跳过。

## 四、 额外发现：仓库双重前缀问题

在 `src/store.ts` 中：
```typescript
export function workspaceRepoDir(root: string, sessionId: string): string {
  return join(root, REPOS_WS_DIRNAME, `session-${sessionSegment(sessionId)}.git`)
}
```
当 DSH 内部的 `sessionId` 自身已带有 `session-`（如 `session-e4700bfd-...`）时，拼接后会变成 `session-session-e4700bfd-...git`。

---

## 五、 解决方案与修复建议

### 1. 彻底修复（插件源码 `src/workspace.ts`）

建议使用成熟的 glob / gitignore 匹配策略，对相对路径 `rel`（保持标准 POSIX `/` 格式）进行整路径匹配：

* **方案 A（直接使用已有的 `picomatch` 依赖）**：
  在 `compileExcludes` 中针对相对路径 `rel` 和文件名 `name` 进行双重/层级匹配，支持包含 `/` 的路径 pattern。
* **方案 B（引入标准 `ignore` 库）**：
  Git 标准规范支持多级规则、根路径锚定、`**` 递归通配符及否定规则 `!`。

### 2. 临时规避方案（用户项目 `.gitignore`）

如果暂时无法更新插件，在项目根目录 `.gitignore` 中避免写带父级路径和前置斜杠的规则，改用纯目录名（插件当前支持在任意层级匹配纯 basename）：

```gitignore
# 临时修改方案：去除前置斜杠和多级父路径
target/
gen/
permissions/
node_modules/
dist/
```
