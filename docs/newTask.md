## 背景

一个会话，长期和ai对话下去，ai可能因为我们的内容太多、话题转移、目标偏差，导致ai偏移目标。或者又因为压缩上下文，慢慢的丢失一些比较重要的细节。



## 思路
在我们长长的会话记录中，选择我们不想让ai记住的任容，把他们给屏蔽掉。
ai可以只看到我们想给他看的内容，在这个基础上，任务继续下去。


```功能名字暂定 精炼会话```

```删除 = 删除/屏蔽 （目前方案不确定，两种皆有可能）```

## 研究方向

dsh 记录了我们的所有会话信息，ai能看到的，ai看不到的全部在这会话记录中，我们可以在 轨迹 页面看到这些信息。
我们的rewind插件，把这些会话内容，全部做成了TURN.start + TURN.end.

## 大概流程
记录当前turn

用户可以选择我们的turn进行删除，假设这个列表[1,2,3,4,5,6,7,8,9]是我们的turn，用户选择[4,5,8]进行删除，列表只剩[1,2,3,6,7,9],可以在这个阶段 对我们的 [1,2,3,6,7,9] 聊天内容进行 上下文压缩（或许会在最后追加一些提示词，告诉ai，我们截断了聊天内容，截断的部分，是不希望你能知道的）。

在当前turn位置，进行分支，快照。保存我们的裁切内容，这样我们的会话就永远存在了一份分支

后续会话，ai 只能看到这些聊天内容，这样我们就可以剔除我们偏离目标的会话内容。



## 注意细节

1. 在没有开始精炼之前，可能已经存在上下文压缩了，我们应该忽略上下文压缩的内容，而是把USER和ASST的原生内容 精炼 到新的分支，这样才能最大成都保证我们的原生语义，并且被压缩的过的内容，ai是看不到的，只能看到被压缩过的。所以我们要在这里处理一些这个细节

2. 由于我们删除/隐藏内容，我们的这个分支会话会和之前上下文不同，也就意味着模型缓存大概率无法复用了。但是用户任然可能短时间的在精炼前的会话或者精炼后的会话直接来回切换，我们总不能每次切换都重构缓存。我们应该只有精炼的时候创建一次缓存，后续来回跳转，应该有各自的缓存可以使用

3. 旧版本插件之间，分支会话缓存都是可以互相使用的，所以切换的时候我们无所谓，但是精炼会话不同，我们应该有视觉检测，当在精炼会话的时候，我们应该把未精炼过的分支变为灰色。反之亦然

4. 我们是否需要给这个分支一个独立的会话id，以确保服务端我们的缓存不会被覆盖。


## ui 操作逻辑
- 现有基础不变
- 鼠标悬停的时候，右边会多一个删除按钮
- 点击删除按钮，此turn变为灰色，代表我们要精炼会话的话，不会有这个turn的内容
- 当已经有被剔除的，或者变为灰色的turn，那么我们的鼠标点击逻辑，会变为 选择/放弃，可以直接去点击别的会话，让其变为灰色
- 当有灰色的turn或者未被选择的turn，history panel 最下角会多一个按钮，暂时就叫精炼会话
- 点击 精炼会话，根据我们的选择/弃选来开始精炼会话
